# ドキュメント評価基準

## 使い方

各項目を `満たす`、`一部満たす`、`満たさない`、`対象外` で評価する。必須条件に `一部満たす` または `満たさない` があれば修正し、最初から評価し直す。加点の合計で必須条件の欠落を相殺しない。

## 必須条件

### 読者と成果

- 対象読者と、読後に行う判断または行動が明確である
- 文書の目的が一つに定まり、異なる種類の情報が無秩序に混在していない
- 完了状態、期待結果、または次の行動が判断できる
- 実行可能性を損なう未定義事項がある場合、文書の先頭で影響とともに示している

### 情報設計

- 最初の画面で結論、全体像、重要な行動を把握できる
- 手順は実際の作業順に並んでいる
- 条件分岐と分岐後の手順が近くにある
- 重要な制約や警告が長い説明に埋もれていない
- 見出しだけを読んでも文書の流れが分かる

### 明確さ

- 主体、対象、手段、条件、完了状態のうち、解釈を揃えるために必要な要素がある
- 「適切に」「対応する」「確認する」などの曖昧な指示に判断基準がある
- 必須、禁止、原則、例外、参考を区別できる
- 非自明な禁止や制約に理由または安全な代替手段がある
- 異なる読者が主要な構成、作業順、責任範囲、完成状態を同じように想像できる

### 必要十分性

- 各記述が判断、行動、安全性、認識の一致の少なくとも一つに寄与する
- コードや設定から容易に確認できる事実を不必要に転載していない
- 同じ情報を重複して説明していない
- 現在の正しい状態を記述し、削除履歴や編集経緯を本文へ残していない
- 詳細を削っても正しく行動できる箇所が残っていない

### 正確性と保守性

- 事実、推論、提案、不明点を区別している
- 元情報の義務、禁止、推奨、可能性の強さを変えていない
- 元情報にない主体、決定権、情報源、権限、成功条件を推測で補っていない
- リンク、パス、コマンド、設定値、コード例を正本と照合している
- 情報の正本が明確で、更新箇所を不必要に増やしていない
- 頻繁に変わる実装詳細を必要以上に固定していない

### 表現と構文

- 図、表、コード例は本文だけより理解を改善している
- 図の流れと視点移動が自然で、重要情報を図だけに閉じ込めていない
- 太字とインラインコードを意味に応じて使い分けている
- Markdownの見出し、リスト、表、リンク、コードフェンスが正しい
- Markdown内でコードフェンスを例示する場合、外側のフェンスが内側より長い

## 最終判定

次の問いへすべて `はい` と答えられる場合だけ完了とする。

1. 読者は全文を読まなくても、目的と全体像を把握できるか
2. 読者は質問せずに次の正しい行動を選べるか
3. 異なる読者が主要な作業と完成状態を同じように想像できるか
4. これ以上短くすると、判断、行動、安全性、認識の一致が悪化するか
5. 現在の正しい情報だけが残っているか
