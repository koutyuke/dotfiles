# ORCA.md

## Orca での Codex 連携

Orca 内で動いているときは、Claude が要件整理・指示・レビュー・報告を担い、コーディングを実装担当、対等な相談を相談役の Codex に任せる。
実装担当が書いたコードは、必ず Claude がレビューしてからユーザーへ報告する。

### 適用条件と使う Skill

- 環境変数 `ORCA_TERMINAL_HANDLE` が設定されているときだけ適用する。セッション中に初めてコーディングか相談を始める前に `printenv ORCA_TERMINAL_HANDLE` で一度確かめる。
- Orca の外、またはユーザーが「Claude が直接書いて」「Codex を使わないで」と指示したときは適用しない。
- worker の起動・待機・再利用・解放は `orchestration` Skill の supervised loop で行い、コマンドと安全規則はその Skill に従う。Claude は worker の完了を待ってレビューするため、完了を待たない `orca-cli` の handoff は使わない。

### 役割

| 役割        | 担当   | 任せること                                                           |
| ----------- | ------ | -------------------------------------------------------------------- |
| coordinator | Claude | 要件整理、作業指示、相談結果の判断、レビュー、検証、ユーザーへの報告 |
| 実装担当    | Codex  | コードの実装・修正・リファクタリング・テスト追加                     |
| 相談役      | Codex  | 設計判断、原因が絞れないバグの仮説出し、Claude の計画への反論        |

- コード変更は実装担当に任せる。指示を書くより直す方が早い数行の機械的修正（typo、import の追加など）と、ドキュメントだけの変更は Claude が直接行ってよい。
- 相談役への相談は、選択によって結果が大きく変わる判断と、Claude だけでは原因を絞れない問題に使う。調べれば分かる事実の確認には使わない。

### 役割ごとの起動設定

`worker-start` には、役割に応じて次のオプションを付ける。モデルや effort を変えるときは、この表だけを直す。

| 役割     | `worker-start` のオプション                         |
| -------- | --------------------------------------------------- |
| 実装担当 | `--agent codex --model gpt-6.1-sol --effort medium` |
| 相談役   | `--agent codex --model gpt-6-astra --effort high`   |

### 作業の流れ

```text
[1. Run を作る] (依頼 1 件につき 1 つ)
   │
   ▼
[2. 相談役に相談する] (必要なときだけ)
   │
   ▼
[3. 実装担当に実装させる]
   │ worker_done
   ▼
[4. Claude がレビューする] ──指摘あり──▶ 3 に戻す
   │ 指摘なし
   ▼
[5. 片付けて報告する]
```

### 相談役に相談する

相談の Task spec には、`orchestration` Skill の Task-spec contract に加えて次を書く。

- Claude の現在の案と根拠、および「同意する前に反論・見落とし・代替案を挙げる」
- 「リポジトリのファイルを編集しない」
- 「回答を `/tmp/orca-codex/<run_id>/<名前>.md` に書き、`worker_done` に `--report-path` を付ける」

相談役の意見は根拠で評価し、そのまま採用しない。意見が割れて決められない場合は、両方の案と根拠をユーザーに示して選んでもらう。

### 実装担当に実装させる

- Task spec は Task-spec contract の 5 項目で書き、完了条件にはプロジェクトの検証コマンドを入れる。
- `--worktree current` で起動する。実装担当が作業している間、Claude は同じ worktree のファイルを編集せず、同じ worktree で同時に動かす実装担当は 1 つまでにする。

### Claude がレビューする

実装担当の `worker_done` を受け取るたびに Claude がレビューする。`worker_done` の要約や実装担当の自己申告を、レビューや検証の代わりにしない。

1. `git status --short` と `git diff` で、変更が指示の範囲内か、無関係な変更や依頼外の依存追加がないかを確かめる。
2. 完了条件のコマンドを Claude 自身が実行し、結果を確かめる。
3. 指摘があれば、指摘と期待する結果を書いた修正指示を同じ実装担当に送り、1 からやり直す。
4. 修正を 2 回繰り返しても指摘が解消しない場合は、相談役に原因を相談するか、状況をユーザーに報告して判断を仰ぐ。

### Claude Code で使うときの注意

- 続きの依頼（相談の追加、修正指示）は、新しく起動せず `--terminal` で同じ worker に送る。worker が直前の文脈を保ったまま作業できる。
- Bash ツールの上限は 600000 ms なので、`orchestration check --wait` の `--timeout-ms` は 540000 にする。
- `orca` が動かない、または worker を起動できない場合は、エラーをユーザーに伝え、Claude が直接作業してよいか確かめる。

### 片付けて報告する

- `orchestration` Skill の完了条件どおり worker を解放し、`/tmp/orca-codex/<run_id>/` を削除する。
- ユーザーへの報告に、実装担当・相談役に任せた内容、Claude のレビューで見つけて直させた点、Claude が実行した検証の結果を含める。
